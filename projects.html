Intelligent Data Platform (IDP)

An end-to-end AutoML platform that turns any uploaded CSV into a trained, explained, and deployment-ready ML model. Upload a dataset — the platform automatically cleans it, detects the problem type (classification, regression, or clustering), trains multiple models, and selects the best one using a configurable business cost matrix.

Model selection goes beyond raw accuracy — a recall-floor guardrail prevents degenerate predictions, and leakage-free SMOTE cross-validation folds ensure evaluation is honest on imbalanced data. An adaptive SHAP explainer (Tree, Linear, or Kernel based on model type) provides per-prediction explanations and global feature importance.

PSI drift detection flags when incoming inference data shifts from the training distribution. Groq LLaMA 3.3 generates a plain-English business report summarizing findings and recommendations, downloadable as a PDF. The system ships with 14 pytest tests and a GitHub Actions CI pipeline.

Key Achievements

  • AUC-ROC 0.981 and AUC-PR 0.848 on 284K-row imbalanced fraud dataset (0.17% positive rate)
  • Cost-aware model selection — optimizes expected business loss, not just accuracy
  • Leakage-free SMOTE — synthetic samples never touch held-out folds
  • Adaptive SHAP — TreeExplainer for trees, LinearExplainer for linear models
  • Reduced training time from 20 to 3 minutes via data-size-aware scaling strategy
  • 14 pytest tests with GitHub Actions CI — verified, not just written

Tech Stack

Python FastAPI React XGBoost SHAP LIME MLflow Groq LLaMA 3.3 MongoDB Atlas imbalanced-learn ReportLab pytest

What I Learned

The most important lesson: a correct earlier refusal of a shortcut (like KernelSHAP on 284K rows) matters more than feature count. Running the code and fixing real bugs — like the runner-up cost-matrix selection bug — built more confidence than any amount of planning.

Global Economic Intelligence Dashboard

A real-time economic intelligence platform covering 190+ countries with AI-generated summaries, machine learning models, live data integration, and interactive visualizations. Built with Flask, D3.js, and Groq LLaMA 3.3.

The platform integrates World Bank API for live economic data, ARIMA time series forecasting for 5-year GDP projections, and Isolation Forest anomaly detection to flag countries with unusual GDP growth patterns. News headlines are analyzed in real-time using VADER sentiment analysis via NewsAPI.

Machine learning features include K-Means clustering to identify economically similar countries and a recession risk predictor that scores countries from 0-100% based on GDP growth, inflation, and unemployment. WebSocket via Flask-SocketIO auto-refreshes data every 30 minutes without page reload.

DailyBrief AI — Personal Intelligence System

A 6-layer AI pipeline that reads your Gmail, analyzes your Google Calendar, and automatically delivers a personalized daily intelligence brief three times per day — even when your PC is off. Deployed 24/7 on Railway cloud.

The pipeline layers work in sequence: Gmail API ingests inbox, Google Calendar API checks schedule, an NLP parser using spaCy and VADER detects deadlines and urgency signals, an XGBoost classifier scores email priorities with a self-improving feedback loop, Groq LLaMA 3.3 generates the personalized brief, and Resend API delivers a beautifully formatted HTML email.

All briefs and email statistics are stored in MongoDB Atlas. An APScheduler cron job triggers delivery at 8:30 AM, 2:00 PM, and 8:00 PM daily. The system runs autonomously without any manual intervention.

Key Achievements

  • 6-layer autonomous pipeline — runs 24/7 without manual intervention
  • Gmail OAuth2 and Google Calendar API integration for real inbox data
  • XGBoost priority classifier with self-improving feedback loop via MongoDB
  • Groq LLaMA 3.3 generates context-aware, personalized brief content
  • Delivers 3 briefs daily (morning, afternoon, evening) via Resend API
  • Deployed on Railway cloud — fully operational without local machine

Python Groq LLaMA 3.3 XGBoost spaCy VADER Gmail API Google Calendar API MongoDB Atlas APScheduler Resend API Railway

RAG PDF Chatbot

This project builds an end-to-end Retrieval-Augmented Generation (RAG) pipeline that allows users to upload any PDF document and ask natural language questions about its content. The system retrieves the most relevant sections from the document and uses a large language model to generate accurate, context-grounded answers.

The pipeline processes PDFs into 500-word overlapping chunks and stores them as 384-dimensional semantic vectors using HuggingFace sentence-transformers (all-MiniLM-L6-v2). When a user asks a question, the system performs semantic search using FAISS to retrieve the top-3 most relevant chunks.

The retrieved context is passed to Google Gemini 2.5 Flash API with a custom prompt engineering template that instructs the model to answer only from the provided context — preventing hallucination and keeping answers grounded in the source document.

Key Achievements

  • Processes PDFs into 500-word overlapping chunks for better context retention
  • Stores 384-dimensional semantic vectors in FAISS for fast retrieval
  • Retrieves top-3 relevant chunks per query using cosine similarity
  • Achieved correct answers on factual queries across 15-page research documents
  • Integrated Gemini 2.5 Flash API with custom prompt engineering

Tech Stack

Python LangChain FAISS HuggingFace Gemini API PyPDF2 Sentence Transformers

What I Learned

Building this project gave me deep hands-on experience with vector databases, semantic search, and prompt engineering — skills that are increasingly central to production AI systems. I learned how chunking strategy significantly impacts retrieval quality.

AutoApply AI — Multi-Agent Job Application Platform

A multi-agent autonomous job application platform where five specialized LLM agents work in sequence to scout job postings, score each one against a user's resume, tailor bullet points, draft cover letters, and run an ATS quality check. Results are shown on a dashboard and emailed as a daily digest.

Agent 1 (Scout) uses Tavily API to find jobs across Greenhouse, Lever, Ashby, and Wellfound. Agent 2 (Analyst) scores each job 0-100 using Groq LLaMA. Agent 3 (Tailor) rewrites resume bullets to match the job. Agent 4 (Cover Letter) drafts a personalized letter. Agent 5 (QC) produces ATS compatibility scores and skill gap analysis.

The system includes JWT authentication, bcrypt password hashing, email-based password reset, per-user data isolation in MongoDB Atlas, PDF resume upload, application status tracking, and an APScheduler daily pipeline run at 8:30 AM EST.

Key Achievements

  • 5-agent pipeline — scout, score, tailor, write, QC in sequence
  • Full-stack deployment: Railway (backend) + Vercel (frontend)
  • JWT auth with email-based password reset via Resend API
  • Per-user data isolation — JWT-decoded email filters all queries
  • PDF resume parsing, application status tracker, private notes per job
  • Validated by a real interview invite from ClearView Healthcare Partners

Tech Stack

Python FastAPI React Groq LLaMA 3.3 Tavily API MongoDB Atlas JWT APScheduler Railway Vercel Resend API

What I Learned

Building a multi-agent system taught me that each agent should have one clear job — it makes the system easier to debug and extend than a single monolithic prompt. The biggest challenge was per-user data isolation and handling JWT auth correctly at scale.

Multi-Agent Atari Boxing with Deep Q-Learning

This project trains two competing Deep Q-Network (DQN) agents to play the Atari Boxing game against each other using the PettingZoo multi-agent environment and PyTorch. The agents learn entirely through self-play — no hardcoded rules or human demonstrations.

Each agent uses a CNN-based DQN architecture consisting of 3 convolutional layers followed by 2 fully connected layers, operating on 4 stacked 84×84 grayscale frames as input. The stacking of frames gives the agent temporal information to infer velocity and direction.

Key RL techniques implemented from scratch include Experience Replay with a 10,000-sample buffer, Target Networks for stable Q-value updates, and Epsilon-Greedy exploration decaying from 1.0 to 0.1 over training. Trained over 200 episodes on a T4 GPU.

Key Achievements

  • Achieved 62%/38% win-rate split between agents after 200 episodes
  • Trained on T4 GPU via Google Colab
  • Implemented Experience Replay (10K buffer) and Target Networks from scratch
  • Preprocessed 210×160×3 RGB frames to 84×84 grayscale using OpenCV
  • Visualized reward curves and win-rate progression using Matplotlib

Tech Stack

Python PyTorch PettingZoo OpenCV Matplotlib Google Colab CUDA (T4 GPU)

What I Learned

This project gave me practical experience with the full DQN training loop and how multi-agent environments introduce non-stationarity that makes training more challenging than single-agent RL.

Customer Shopping Behavior Analysis

An end-to-end data analytics project analyzing 3,900 retail transactions to uncover customer purchasing patterns, segment performance, and revenue distribution. The project covers the full analytics pipeline from raw data ingestion and SQL analysis to interactive Power BI visualization.

The SQL analysis uses 10 complex queries including Common Table Expressions (CTEs) and window functions to calculate running totals, rank customers by lifetime value, and identify seasonal purchase trends — all executed in PostgreSQL.

The final Power BI dashboard reveals key business insights including a $157K vs $75K gender revenue split and identifies Young Adults as the top customer segment with $62,143 in total spend.

Key Achievements

  • Analyzed 3,900 retail transactions end-to-end
  • Wrote 10 SQL queries using CTEs and window functions
  • Uncovered $157K vs $75K gender revenue split
  • Identified Young Adults as top segment with $62,143 total spend
  • Built interactive Power BI dashboard for business stakeholders
