CausalLens

A causal inference platform covering the full lifecycle of an experiment: designing it, monitoring it under continuous observation, and estimating the effect afterwards. It implements CUPED variance reduction, difference-in-differences, propensity score matching, doubly robust AIPW, Bayesian A/B testing, T-Learner uplift modelling, and always-valid sequential inference.

Every estimator is validated against synthetic data with a known injected effect, so bias is measurable rather than assumed. More importantly, each one ships a diagnostic for the specific assumption it depends on: CUPED reports residual correlation, PSM reports covariate balance and sensitivity to hidden bias, and DiD reports a parallel-trends placebo test.

The failures are kept and documented rather than patched. DiD's confidence interval undercovers at 83% instead of the nominal 95%, and the placebo test explains exactly why. AIPW beats matching on synthetic data and loses badly on the LaLonde benchmark, and the overlap diagnostic explains that too.

Key Achievements

  • Cut confounding bias from 1.82 naive to -0.16 with PSM and -0.05 with AIPW across 30 random seeds
  • Trimmed outcome variance 47.2% under CUPED, cutting required sample size by the same margin
  • A placebo test measured a +0.45 per period pre-trend from pre-treatment data alone, which predicted the realized DiD bias of 0.37
  • Validated externally on the LaLonde NSW benchmark, recovering $1,637 against a $1,794 experimental truth from a -$8,498 naive baseline
  • Beat random targeting by 128.4% AUUC on the 223K-row Criteo uplift dataset
  • A pipeline-refitting bootstrap exposed 58% understated standard error in the conventional PSM interval
  • 45 pytest tests under GitHub Actions, including one that proves the placebo test correctly passes when the assumption holds

Tech Stack

Python Statsmodels Scikit-Learn SciPy NumPy Pandas Matplotlib Streamlit pytest GitHub Actions

What I Learned

A correct-looking point estimate is not evidence that a method worked. It can be right by luck, or wrong in a way the final number hides. Building the diagnostic that would catch each estimator lying taught me more than implementing the estimators did.

AgentAudit

An AI agent evaluation harness built around Scout, a ReAct-style data analyst that answers questions about any uploaded CSV. The project is less about building the agent than about proving whether it works: a hand-written 29-task golden set, dual LLM judges validated against human scoring, regression detection, and adversarial red-teaming.

The claim it tries to earn is that an evaluation harness has to be validated too. A judge that scores answers is itself a model that can be wrong, so it gets checked against human scoring. A guardrail is only useful if you know which attacks it misses, so the red-team pass reports failures as prominently as wins. And a regression suite is only meaningful if it catches something, so a bug was deliberately introduced to see whether it would.

The red team exposed a hallucination that neither keyword guardrail could see: the agent invented a customer segment absent from the data. That gap motivated a third guardrail, which inverts the logic of the other two by building an allowlist from the dataset itself rather than a denylist of bad patterns.

Key Achievements

  • Cohen's kappa 0.774 judge-vs-human agreement, reported with a bootstrap 95% CI of 0.46 to 1.00 on 15 hand-scored tasks
  • A deliberately introduced operator swap dropped the pass rate 83% to 50%, caught by automated regression checks
  • The bug was proved by arithmetic, not just a red test: task 11 reported 91 orders instead of 29, and 120 minus 29 equals 91 exactly
  • Red-team sweep cut unsafe responses 86% to 57% post-guardrail, reproducing exactly after a mid-project model migration
  • Built a grounding guardrail validating entity mentions against the dataset, catching invented category names two keyword filters missed
  • Documented the failure the new guardrail still cannot catch: invented numbers attached to real category names
  • 23 pytest tests under GitHub Actions, all running offline without API calls

Tech Stack

Python LangChain LangGraph Groq Scikit-Learn Pydantic Streamlit Plotly ReportLab pytest

What I Learned

Groq deprecated both judge models mid-project, which broke every script at once. Centralising the model IDs and documenting the migration taught me more about production ML fragility than the evaluation work did. Also: a test that always fails proves nothing, which is why the specificity check matters more than the detection.

GlassBox ML

An end-to-end AutoML platform that turns any uploaded CSV into a cleaned, explained, deployment-ready model. It inspects data quality and flags target leakage before modelling, selects the best model by business cost rather than raw accuracy, explains predictions with SHAP, checks for drift, and writes an AI-generated PDF report.

Model selection uses a configurable cost matrix that converts each model's confusion matrix into an expected dollar cost, with a recall-floor guardrail that disqualifies degenerate "predict nothing" models. Leakage-free SMOTE runs inside each cross-validation fold so synthetic samples never touch held-out data.

An adaptive SHAP explainer picks TreeExplainer for tree models, LinearExplainer for linear ones, and a bounded KernelExplainer otherwise, because KernelSHAP on 284K rows is impractical. PSI and KS drift detection flags when inference data shifts from the training distribution.

Key Achievements

  • AUC-ROC 0.981 and AUC-PR 0.848 on a 284K-row fraud dataset with a 0.17% positive rate
  • The cost-aware selector chose XGBoost over Logistic Regression despite comparable AUC-ROC, because LR's 0.06 precision produced a far higher expected business cost
  • Cut training time from 20 minutes to 3 via data-size-aware scaling, with SVM auto-excluded above 20K rows and logged explicitly
  • Leakage-free SMOTE inside CV folds, preventing inflated metrics
  • Data quality inspection assigns a 0 to 100 score and flags leakage before any model is trained
  • 14 pytest tests under GitHub Actions covering problem-type detection, preprocessing, cost matrix, and drift

Tech Stack

Python FastAPI React XGBoost SHAP LIME Scikit-Learn imbalanced-learn Groq MongoDB Atlas ReportLab pytest

What I Learned

Refusing a shortcut matters more than feature count. KernelSHAP on 284K rows would have been technically possible and practically useless, so the explainer picks its method by model type instead. Running the code and fixing real bugs, like the runner-up cost-matrix selection bug, built more confidence than any amount of planning.

DailyBrief AI, a personal intelligence system

A 6-layer AI pipeline that reads your Gmail, analyzes your Google Calendar, and automatically delivers a personalized daily intelligence brief three times per day, even when your PC is off. Deployed 24/7 on Railway cloud.

The layers work in sequence: Gmail API ingests the inbox, Google Calendar API checks the schedule, an NLP parser using spaCy and VADER detects deadlines and urgency signals, an XGBoost classifier scores email priorities with a self-improving feedback loop, an LLM generates the personalized brief, and Resend API delivers a formatted HTML email.

All briefs and email statistics are stored in MongoDB Atlas. An APScheduler cron job triggers delivery at 8:30 AM, 2:00 PM, and 8:00 PM daily. The system runs autonomously without manual intervention.

Key Achievements

  • 6-layer autonomous pipeline running 24/7 without manual intervention
  • Gmail OAuth2 and Google Calendar API integration for real inbox data
  • XGBoost priority classifier with a self-improving feedback loop via MongoDB
  • LLM-generated context-aware, personalized brief content
  • Delivers 3 briefs daily (morning, afternoon, evening) via Resend API
  • Deployed on Railway cloud, fully operational without a local machine

Tech Stack

Python Groq XGBoost spaCy VADER Gmail API Google Calendar API MongoDB Atlas APScheduler Resend API Railway

What I Learned

Building a truly autonomous pipeline taught me that reliability matters more than features. Handling OAuth token expiry in production, managing rate limits across projects, and designing a self-improving feedback loop gave me real production ML engineering experience.

AutoApply AI, a multi-agent job application platform

A multi-agent autonomous job application platform where five specialized LLM agents work in sequence to scout job postings, score each one against a user's resume, tailor bullet points, draft cover letters, and run an ATS quality check. Results appear on a dashboard and arrive as a daily digest email.

Agent 1 (Scout) uses the Tavily API to find jobs across Greenhouse, Lever, Ashby, and Wellfound. Agent 2 (Analyst) scores each job 0 to 100. Agent 3 (Tailor) rewrites resume bullets to match the job. Agent 4 (Cover Letter) drafts a personalized letter. Agent 5 (QC) produces ATS compatibility scores and skill gap analysis.

The system includes JWT authentication, bcrypt password hashing, email-based password reset, per-user data isolation in MongoDB Atlas, PDF resume upload, application status tracking, and an APScheduler daily pipeline run at 8:30 AM EST.

Key Achievements

  • 5-agent pipeline that scouts, scores, tailors, writes, and quality-checks in sequence
  • Full-stack deployment on Railway (backend) and Vercel (frontend)
  • JWT auth with email-based password reset via Resend API
  • Per-user data isolation using a JWT-decoded email to filter all queries
  • PDF resume parsing, application status tracker, and private notes per job

RAG PDF Chatbot

An end-to-end Retrieval-Augmented Generation pipeline that lets users upload any PDF and ask natural language questions about its content. The system retrieves the most relevant sections and uses a large language model to generate answers grounded in the source document.

The pipeline processes PDFs into 500-word overlapping chunks and stores them as 384-dimensional semantic vectors using HuggingFace sentence-transformers (all-MiniLM-L6-v2). When a user asks a question, the system performs semantic search using FAISS to retrieve the top 3 most relevant chunks.

The retrieved context goes to Google Gemini 2.5 Flash with a prompt template instructing the model to answer only from the provided context, which prevents hallucination and keeps answers grounded. When the answer isn't in the document, it says so.

Key Achievements

  • Processes PDFs into 500-word overlapping chunks for better context retention
  • Stores 384-dimensional semantic vectors in FAISS for fast retrieval
  • Retrieves top 3 relevant chunks per query using cosine similarity
  • Returns correct answers on factual queries across 15-page research documents
  • Refuses honestly when the answer is not present in the source document

Tech Stack

Python LangChain FAISS HuggingFace Gemini API PyPDF2 Sentence Transformers

What I Learned

Building this gave me hands-on experience with vector databases, semantic search, and prompt engineering. I learned how much chunking strategy affects retrieval quality, and that an honest refusal is a feature rather than a failure.

Multi-Agent Atari Boxing with Deep Q-Learning

Two competing Deep Q-Network agents trained to play Atari Boxing against each other using the PettingZoo multi-agent environment and PyTorch. The agents learn entirely through self-play, with no hardcoded rules and no human demonstrations.

Each agent uses a CNN-based DQN architecture of 3 convolutional layers followed by 2 fully connected layers, operating on 4 stacked 84 by 84 grayscale frames. Stacking frames gives the agent temporal information to infer velocity and direction.

Key RL techniques implemented from scratch include Experience Replay with a 10,000-sample buffer, Target Networks for stable Q-value updates, and Epsilon-Greedy exploration decaying from 1.0 to 0.1. Trained over 200 episodes on a T4 GPU.

Key Achievements

  • Achieved a 62% to 38% win-rate split between agents after 200 episodes
  • Trained on a T4 GPU via Google Colab
  • Implemented Experience Replay and Target Networks from scratch
  • Preprocessed 210 by 160 by 3 RGB frames to 84 by 84 grayscale using OpenCV
  • Visualized reward curves and win-rate progression using Matplotlib

Tech Stack

Python PyTorch PettingZoo OpenCV Matplotlib Google Colab CUDA

What I Learned

This gave me practical experience with the full DQN training loop, and showed how multi-agent environments introduce non-stationarity that makes training harder than single-agent RL.
